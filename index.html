Vibeflow Plus

Vibeflow turns a prompt into a live preview. Vibeflow Plus runs that same process on your own machine, inside the real project directory: every file it touches is right there to open, review, and comment on, with the preview updating live as it works.

Foundation

Built on DeepSeek Harness

Vibeflow Plus is built on DeepSeek Harness (dsh), an MIT-licensed, plugin-based agent runtime similar to Claude Code or Cursor's agent mode, reachable as a CLI or through its own web interface. Every part of it, from model adapters to the session log itself, is a swappable plugin.

What's different

Structured by design

Every session starts from a stated goal and a logged plan, so what the agent is doing always traces back to what it was asked to do. Before any file changes, a checkpoint is taken automatically, so a step can be undone without losing the surrounding conversation. What the agent remembers carries over between sessions, and anything that looks like a secret is stripped out before it's ever written down.

Bring the model provider you already use and trust. Focused subagents handle inspection, coding, and testing separately, each with its own narrower set of permissions.

Tool and shell-command access is set rule by rule, not with one broad switch: an AST-based tokenizer tells a safe git status from a destructive rm -rf, so each command gets its own allow, ask, or deny. A session's context can be reset on demand with /clear, and read back afterward with /cleared, without losing anything from the durable log.

Getting in

One path grows up, one starts fresh

Only one of the two ways in starts in Vibeflow, and today that bridge is a conversation, not a pipeline: pressing Publish hands off to a person, not a running project. The plan is for that same button to carry a Vibeflow prototype straight into Vibeflow Plus with its files intact. Someone who already knows what they want can skip that step entirely and open Vibeflow Plus directly, spec in hand.
